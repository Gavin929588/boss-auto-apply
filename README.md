# boss-auto-apply
# 智能投递助手（BOSS直聘 / 鱼泡直聘）

一个运行在**你自己浏览器**里的 Chrome 扩展：按你写好的一套规则，在招聘网站上逐个筛选岗位、自动打招呼、把结果记账，遇到验证码自动停下。

不破解接口、不绕过验证、不代发简历，只是把你每天重复的「翻列表 → 看岗位 → 点沟通 → 贴招呼语」这套动作在本地模拟一遍。

| 项    | 值                                      |
| ---- | -------------------------------------- |
| 当前版本 | **3.1.0**                              |
| 支持平台 | BOSS直聘（`zhipin.com`）、鱼泡直聘（`yupao.com`） |
| 浏览器  | Chrome / Edge（Chromium 内核，Manifest V3） |
| 数据存放 | 全部在本机 `chrome.storage.local`，不联网、不上传   |
| 代码规模 | 约 5,900 行纯 JS（含页面 900 行），无第三方依赖、无远程脚本  |

---

## 一、这个插件做什么

### 会做的事

- 按「关键词 + 城市」搜索岗位，自动翻页，一页一页往下看
- 按你的筛选条件（岗位名、薪资、公司名、城市、经验、学历、规模、融资、外包、活跃度、自定义正则）判断每个岗位要不要投
- 符合条件就点「立即沟通」，在沟通页填入**你自己写的招呼语**并发送
- 已经打过的招呼不再重复打（同一岗位、同一公司都算）
- 每天有次数上限，每次之间有随机间隔，被风控拦下就停
- 可以设定只在某些天的某些时段自动运行，跑完一段自动暂停、下一段接着跑
- 每个平台**各自一整套配置**，切平台不会互相覆盖、也不会拿错规则跑错网站

### 不会做的事

- ❌ 不破解平台接口、不伪造请求、不模拟登录
- ❌ 不绕过验证码 / 滑块 / 短信验证 —— 遇到就暂停，等你手动处理
- ❌ 不改你的简历、不替你回复 HR 的消息
- ❌ 不批量群发骚扰（有上限、有间隔、有去重）
- ❌ 不采集岗位数据上传到任何服务器

## 二、核心特性一览

| 特性             | 说明                                                         |
| -------------- | ---------------------------------------------------------- |
| **双平台独立配置**    | 搜索任务、筛选规则、投递行为、定时时段、页面选择器、投递记录、公司名单，全部按平台分开存，切平台不会串        |
| **每平台内置固定规则表** | 规则写在代码里（`BAA.PLATFORM_PRESETS`），选中平台即套用，改乱了可一键还原，还原只影响当前平台 |
| **切平台自动跳转**    | 面板上点平台按钮 → 浏览器跟着打开/切换到该平台页面；设置页切换则不动你的标签页                  |
| **启动前登录自检**    | 用「登录会话 cookie + 页面标记」双信号判定，登录页/首页/搜索页都能判；未登录就暂停等待，不盲目执行    |
| **登录后自动接上**    | 检测到登录成功无需再点开始，自动打开搜索结果页继续跑（可关）                             |
| **自定义招呼语**     | 支持 `{岗位} {公司} {城市} {薪资}` 变量，可在沟通页自动填充并发送，也可只填不发送等你确认       |
| **收件人校验**      | 发送前比对会话头与目标岗位，防止把招呼语发给上一个 HR；严格模式下不匹配就不发                   |
| **三层去重**       | ① 同一岗位（job id）② 同一公司（公司名归一化）③ 平台按钮已变「继续沟通 / 继续聊」           |
| **限速与日上限**     | 每单随机间隔、翻页间隔、每日上限、单岗位重试次数，全部可调                              |
| **风控熔断**       | 命中「安全验证 / 操作过于频繁 / 登录已失效」等关键词立即暂停                          |
| **固定时段定时执行**   | 按本机时间判断，支持多时段、跨午夜、周末/工作日，时段结束自动暂停并保留进度                     |
| **断点自愈**       | 自愈守卫 + 后台看门狗 + 单岗位硬超时，页面意外重载或状态卡住会自动接上                     |
| **本地记账与清单**    | 投递流水、日志、已打招呼公司名单都能查，公司可单家删除让它重新进入投递范围                      |
| **配置导入导出**     | 规则可导出为 JSON 备份/分享，不含账号、Cookie、简历内容                         |
| **零投递诊断**      | 本轮一个都没投时，日志直接告诉你主要卡在哪个条件上                                  |

## 三、工作流程

```
① 选平台          面板点「BOSS直聘 / 鱼泡直聘」
      ↓           浏览器打开/切换到该平台，配置同步切到该平台那一套
② 登录自检        后台读 cookie + 页面已登录标记 → ok / expired / guest
      ↓           未登录：暂停并提示「去登录」，等你扫码
③ 加载任务        取该平台的搜索任务队列（关键词 + 城市）
      ↓
④ 搜索列表        URL 模板生成搜索页，等岗位卡片和沟通按钮都出现
      ↓
⑤ 逐卡判断        解析岗位 → 基础筛选 → 高级规则 → 岗位去重 → 公司去重
      ↓           每条不通过都写进日志，并统计「主要卡在哪个条件」
⑥ 点沟通          点卡片进入详情面板（BOSS）或打开详情页（鱼泡）→ 点沟通按钮
      ↓
⑦ 落地沟通页      等输入框就绪 → 校验收件人 → 填招呼语 → 发送
      ↓
⑧ 记账 + 返回      写入本地流水（岗位/公司/时间/平台）→ 整页重载回搜索页
      ↓
⑨ 下一页 / 下一任务 翻页到上限或列表不再变化 → 换下一个任务
      ↓
⑩ 收尾            达到日上限 / 页数上限 / 任务跑完 → 汇总并停止
```

全程受三样东西约束：**每日上限**、**每单间隔**、**验证码熔断**。任何一环触发都会立刻停下，不会硬跑。

## 六、投递流程的两个分支

两个平台的页面结构完全不同，走的是两条实现路径。

### BOSS直聘：搜索页内沟通

```
搜索页 li.job-card-box 列表
   ↓ 读取 .job-name / .boss-name / a[href*="job_detail"]
   ↓ 点击卡片 → 右侧详情面板切换（等 detailWaitMs）
   ↓ 校验详情岗位 ID 与卡片一致（strictDetailMatch）
   ↓ 点 a.op-btn-chat「立即沟通」
   ↓ BOSS 跳转到 /web/geek/chat 并自动选中新会话
   ↓ 等 #chat-input[contenteditable] 就绪
   ↓ 校验收件人（会话头 vs 目标公司/岗位）
   ↓ 填入招呼语 → 点 button.btn-send 发送（不可用则 Enter 兜底）
   ↓ 记账 → 整页重载回搜索页
```

BOSS 的搜索列表**没有「下一页」按钮**，是无限滚动 + URL 分页。插件用 `&page=N` 翻页；如果翻页后岗位列表与上一页完全相同，判定已到末页并停止，不会无限翻下去。

### 鱼泡直聘：详情页新标签沟通

```
列表页 a[href^="/zhaogong/"] 卡片
   ↓ 卡片本身是链接（target=_blank）→ 新标签打开详情页
   ↓ 详情页落地（非 /zhaogong/ 页面则跳过）
   ↓ 点 span.addag「免费聊」
   ↓ 页面内 IM 窗口出现（fish-editor 的 contenteditable，不是 textarea）
   ↓ 填入招呼语 → 点 button.btn-send 发送
   ↓ 记账 → 关闭新标签，回到列表继续
```

鱼泡的按钮在建立会话后会从「免费聊」变&#x6210;**「继续聊」**，插件把两种文案都当作「已沟通」，不会重复点。

## 七、筛选规则全集

一个岗位要「过关」，必须依次通过下面所有判断。任何一条不通过都不会投递，并会把原因写进日志（括号里是日志里出现的原文）。

### 岗位名（6 条）

| 条件      | 触发跳过                               |
| ------- | ---------------------------------- |
| 岗位名包含任一 | 一个都没命中（`岗位名未命中包含词`）                |
| 必须同时包含  | 缺任意一个（`岗位名未同时命中全部词`）               |
| 排除词     | 命中任一（`岗位名命中排除词`）                   |
| 正则      | 不匹配（`岗位名正则不匹配`）/ 写法有误（`岗位名正则写法有误`） |
| 解析      | 读不出名称（`未能解析岗位名称`）                  |

### 公司名（4 条）

`公司名未命中包含词`、`公司名命中排除词`、`公司名正则不匹配`、`公司名正则写法有误`

|   |   |
| - | - |

> 注意：包含词是**子串匹配**，不用填正则，也不能写成 `A|B`。想同时限定多家公司请加多行。

### 标签 / JD 文本（2 条）

`未命中期望标签`、`命中排除标签`

### 硬条件（10 条）

| 条件    | 判定方式                                          |
| ----- | --------------------------------------------- |
| 城市    | 卡片上的「城市·区域」不含任一指定城市 → `城市不符`                  |
| 薪资下限  | 岗位薪资**上限**低于你填的「期望最低月薪」→ `薪资上限低于期望下限`         |
| 薪资上限  | 岗位薪资**下限**高于你填的「薪资上限」→ `薪资下限高于设置上限`（用于过滤虚高岗位） |
| 经验    | `经验要求不符`                                      |
| 学历    | `学历要求不符`                                      |
| 公司规模  | `公司规模不符`                                      |
| 融资阶段  | `融资阶段不符`                                      |
| 外包    | 命中外包/驻场/派遣特征 → `疑似外包/驻场岗位`                    |
| 发布时长  | 超过设定天数 → `发布过久`                               |
| HR 活跃 | 只投活跃时，HR 不在线 → `HR 不活跃`                       |

### 高级规则（1 条）

自定义规则组不满足 → `高级规则未满足`（与基础筛选是「并且」关系；规则组内部可选 AND / OR）

## 八、招呼语

在「投递行为 → 招呼语」里配置，支持变量：

| 变量     | 替换为      | 别名          |
| ------ | -------- | ----------- |
| `{岗位}` | 岗位名称     | `{job}`     |
| `{公司}` | 公司名称     | `{company}` |
| `{城市}` | 城市 / 区域  | —           |
| `{薪资}` | 卡片上的薪资原文 | —           |

默认模板：

```
您好，我看到贵司的「{岗位}」岗位，与我的经历比较匹配，方便进一步沟通吗？
```

两个开关要分清：

- **自动填写自定义招呼语**：控制是否在沟通页填入你的模板
- **自动点击发送**：关掉后只填入、不发送，由你手动确认

另外 BOSS 在你点「立即沟通」时**平台自己可能已经发出一条默认招呼语**，插件发的是你模板里那条，两条会同时出现在会话里 —— 这是平台行为，不是重复发送。

**收件人校验**是防错发的关键：沟通页可能还停留在上一个 HR 的会话，插件会在发送前比对会话头与目标岗位。建议保持「发送前校验收件人」开启；把「严格模式」也打开的话，不匹配就干脆不发（宁可漏一单，不发错人）。

## 九、去重：三层防护

| 层级    | 依据                                 | 效果               |
| ----- | ---------------------------------- | ---------------- |
| ① 岗位级 | 平台岗位 ID（如 `/job_detail/<id>.html`） | 同一岗位在「去重天数」内不重复投 |
| ② 公司级 | **公司名归一化后比对**                      | 同一家公司挂多个岗位时，只打一次 |
| ③ 页面级 | 沟通按钮文案已变成「继续沟通 / 继续聊 / 已沟通」        | 平台侧已建立会话的直接跳过    |

公司名归一化（`BAA.companyKey`）只抹写法差异，**不抹行业词**：

| 会被认成同一家             | 不会认成同一家           |
| ------------------- | ----------------- |
| `深圳市华信汇通科技`         | `深圳市华信汇通科技`       |
| `深圳市华信汇通科技有限公司`     | `深圳市华信汇通**网络**科技` |
| `深圳市华信汇通科技有限公司（深圳）` |                   |
| 前后带空格、全角括号的写法       |                   |

归一化规则：全角括号转半角、去掉 `【】[]`、去掉 `(...)` 分部后缀、去掉空白与标点、去掉末尾的 `有限责任公司 / 股份有限公司 / 有限公司 / 分公司`。

**管理已打招呼的公司**：设置页 → 数据与备份 → 「已打招呼的公司（本地记录）」。可搜索公司名、看到岗位数与最近打招呼时间、点「删除」让这家公司重新进入投递范围。面板顶部的「已记录 N 家公司」与该清单口径一致。

关闭「同一家公司只打一次招呼」即恢复成只看岗位 ID 去重（适合同一家公司确实有多个不同岗位都想投的情况）。

## 十、登录态自检

判定由后台统一执行，不依赖当前停在哪个页面（登录页 / 首页 / 搜索页都能判）。

### 判定逻辑

```
读该平台的登录会话 cookie（强信号，只有真正登录后才存在）
        ↓ 有 cookie
   看任一该平台标签页上的「已登录」标记
        ↓ 显示游客态        ↓ 否则
   expired（会话已失效）    ok
        ↓ 无 cookie
   看页面标记
        ↓ 已登录菜单        ↓ 游客入口可见      ↓ 都没匹配到
      ok（靠页面判定）    required（请先登录）  required（请刷新）
```

最终状态只有三种：`ok` / `expired` / `required`，同时记录「判定来源」（`cookie` / `dom` / `cookie+dom`）。登录页会被特殊排除 —— 登录页对已登录用户也会显示游客表单，不能据此判失效。

### 两个平台的信号差异（实测）

|            | BOSS直聘                                | 鱼泡直聘                                                                 |
| ---------- | ------------------------------------- | -------------------------------------------------------------------- |
| 强信号 cookie | `zp_at`、`geek_zp_token`、`tgt`         | `TOKEN`（`.yupao.com`）、`ROLE`（`.www.yupao.com`）                       |
| 已登录标记      | `.user-nav`、`.nav-figure`、头像 / 「我的简历」 | `#YPHeader a[href^="/user/"]`、「退出登录」                                 |
| 游客标记       | 「登录/注册」按钮                             | 「登录丨注册」（**注意：未登录时页面里也会藏一个 display:none 的同名元素，必须判可见性**）               |
| 易误判项       | —                                     | `USERID` / `current_identity` 这两个 cookie 名**在会话失效后仍然残留**，不能单独作为已登录证据 |

因为鱼泡存在上述「假信号」，判定必须做 cookie + DOM 交叉校验：cookie 名命中后，还要看同平台页面是否呈现游客态；是则判 `expired`（会话已失效）而不是 `ok`。

### 未登录时的行为

1. 任务暂停，日志写 `启动被阻止：当前页面是「X」，但插件选的是「Y」…` 或 `登录态自检：required（…）`
2. 面板提示，`去登录` 会直接打开该平台登录入口并尝试点开弹窗
3. 若开启「自动等待登录」，插件按 `loginPollSec` 轮询，检测到登录成功就自动打开搜索结果页继续，无需再点开始
4. 超过 `loginWaitSec` 仍未登录则停在等待状态

## 十一、定时执行

按**本机时间**判断，不需要打开面板，后台每分钟检查一次。

| 配置     | 说明                                                           |
| ------ | ------------------------------------------------------------ |
| 启用     | 总开关，默认关闭，不影响手动操作                                             |
| 执行日    | 每天 / 工作日 / 周末，或任选星期；一个都不选 = 永不自动执行                           |
| 时间段    | 可加多个，**支持跨午夜**（如 `22:00 - 02:00`，按「开始」那天算执行日）；开始与结束相同视为无效并忽略 |
| 时段结束动作 | 自动暂停（下时段继续，保留进度）/ 自动停止（下时段重新开始）                              |
| 自动开标签  | 时段开始时若没有该平台搜索页，自动新开                                          |
| 后台打开   | 新标签不抢焦点                                                      |
| 系统通知   | 自动开始/暂停时发通知                                                  |
| 拦截后重试  | 被风控或等待登录时，下一个时段自动重试（默认关，更安全）                                 |
| 开机即开始  | 浏览器启动时若正处于时段内，立即开始                                           |

**手动点「暂停 / 停止」后，本次时段内不再自动启动**，到下一个时段才恢复；想立刻放开用面板的「恢复自动」。

定时同样是**按平台**的：只会按「当前平台」的那套时段调度。想让鱼泡按自己的时段跑，先把平台切到鱼泡。

## 十二、稳定性设计

自动化最难的不是「投出去」，而是「连续投不卡住」。这里有四层保险：

| 机制         | 作用                                                                            |
| ---------- | ----------------------------------------------------------------------------- |
| **整页重载返回** | 投完一单回搜索页时用强制重载，而不是浏览器后退 —— 后退会命中 bfcache，页面脚本看似活着但任务循环已退出，表现为「状态显示运行中，却一个都不投」 |
| **自愈守卫**   | 每 `resumeGuardMs`（默认 1.2 秒）检查一次状态机；页面重载导致循环中断时自动接上，日志写 `自愈守卫：页面重载后已自动接上任务`    |
| **后台看门狗**  | 后台每 30 秒检查心跳，超过 `watchdogStaleSec`（默认 10 秒）未更新就兜底恢复，日志写 `看门狗：检测到任务停滞，已自动恢复运行` |
| **单岗位硬超时** | 每个岗位的动作有 `actionTimeoutMs`（默认 20 秒）上限，超时强制跳过，永不无限等待                           |

另外还有**平台守卫**：每个页面的脚本会先确认「我这页属于哪个平台」，与当前配置的平台不一致就直接拒绝启动，日志写 `启动被阻止：本页属于 BOSS直聘，当前配置是 鱼泡直聘`。这是为了防止「切了平台，页面没切」时拿错规则乱跑。

## 十三、本地数据与隐私

### 存储位置与键

全部在 `chrome.storage.local`（浏览器本地，卸载扩展即清空）：

| 键                         | 内容                                                        |
| ------------------------- | --------------------------------------------------------- |
| `baa.config`              | 全部配置（含 `overrides.{boss,yupao}` 两套平台配置、`tasksByPlatform`） |
| `baa.state`               | 运行时状态：进度、统计、当前任务、心跳、阶段                                    |
| `baa.history`             | 投递流水，按岗位 ID 存：公司、岗位名、时间、平台、是否已发招呼语                        |
| `baa.logs` / `baa.bglogs` | 运行日志（各上限 300 条，自动滚动）                                      |
| `baa.schedule`            | 定时运行态（当前时段、跳过标记）                                          |
| `baa.autostart`           | 定时/自动启动的交接标记                                              |
| `baa.pending`             | 投递落地过程中的临时记录                                              |
| `baa.login`               | 登录自检快照：**只存判定结果 + 时间 + 来源，不存任何 cookie 值**                 |

### 隐私边界

- 没有任何网络请求发往第三方服务器；代码里无埋点、无远程脚本
- 不读简历内容、不读聊天记录（只读当前会话头用于核对收件人）
- 导出的配置 JSON 不含账号、Cookie、简历、投递记录
- 真正的登录凭据始终由浏览器自己管理，插件只在本地读取判定「是否登录」
- 「清除本平台 Cookie」会清掉该平台的登录态，用于退出登录或换号

## 十四、安装与首次使用

### 安装

1. 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的那一层）
4. 更新版本时，回到该页面点扩展卡片上的**刷新**按钮即可，不必卸载重装（配置不会丢）


### 首次使用（推荐顺序）

1. **先登录**：面板点对应平台 → 「去登录」→ 在该平台页面完成扫码/验证码登录 → 面板显示「已登录」
2. **先模拟**：设置 → 投递行为 → 勾上「模拟运行」，点开始，看日志里筛选是否符合预期（这一步不点任何按钮）
3. **看诊断**：如果本轮 0 投递，日志会写清主要卡在哪个条件，据此调筛选
4. **小量试投**：关掉模拟运行，把每日上限调到 5，跑一轮，确认招呼语真的发出去了（去平台会话页看）
5. **放开跑**：上限调到 20–50，间隔 12 秒以上，需要的话开定时

### 频率建议

每日 20–40 次、间隔 12 秒以上。再快既容易被判定异常，也容易把不合适的岗位投出去。

## 十五、排错手册

按日志原文查：

| 日志原文（摘录）                                       | 含义                 | 怎么处理                                   |
| ---------------------------------------------- | ------------------ | -------------------------------------- |
| `启动被阻止：当前页面是「BOSS直聘」，但插件选的是「鱼泡直聘」`             | 浏览器停在了另一个平台        | 面板切到该平台，或点「去登录」让它跳过去                   |
| `页面导航被拒绝：…域名`                                  | 页面属于 A 平台却要跳 B 平台  | 同上；正常流程下不该出现（导航校验已改为按页面自身平台判断）         |
| `登录态自检：required（…请先登录）` / `expired（…会话已失效）`    | 未登录或会话过期           | 面板点「去登录」重新登录                           |
| `未识别到岗位卡片，请点「识别当前页」校准选择器`                      | 选择器没命中（平台改版）       | 面板点「识别当前页 / 校准」，看哪几个选择器没命中，改设置页「页面选择器」 |
| `本轮 0 投递：评估 N 个岗位，跳过 N 个（主要命中：…）`              | 全被筛选条件挡住           | 按提示放宽对应条件；顺手检查「每页最多处理数」是否被设成 1         |
| `本轮参数：… 每日上限 50 / 每个任务最多 5 页 / 每页最多 不限 个`      | 启动时打印的实际生效参数       | 用来确认配置是否真的读到了（每个平台各打各的）                |
| `「每页最多处理数」= 1` 或 `「每个任务最多页数」= 1`               | 严重限制，几乎不可能投出去      | 前者设 0（不限），后者设 5 以上                     |
| `已达到每日投递上限`                                    | 今日额度用完             | 调高上限或等次日 0 点（按平台各自计数）                  |
| `跳过 X / Y：该公司已于 M-D HH:MM 打过招呼（当时岗位：…），本地已有记录` | 公司级去重命中            | 想重投这家：设置 → 数据 → 已打招呼的公司 → 删除该家         |
| `招呼语已填入但未能发送：发送按钮始终不可用` / `招呼语未发送：…`           | 输入框或发送按钮没就绪        | 调大「等待聊天输入框 / 等待发送按钮可用」；确认没被平台弹窗遮挡      |
| `收件人未匹配但按设置继续发送`                               | 会话头与目标岗位不一致        | 建议开「严格校验收件人」；同时确认沟通页没停留在旧会话            |
| `停止投递：…验证…`                                    | 命中风控关键词            | 手动去页面处理验证，处理完点继续；当天可先停一停               |
| `未找到翻页按钮，改用 URL 分页到 page=N`                    | 平台没有下一页按钮（BOSS 常态） | 正常现象，不用管                               |
| `自愈守卫：…` / `看门狗：…`                             | 自动恢复生效过            | 正常，出现说明兜底机制在工作                         |
| 状态一直「运行中」但日志不动                                 | 页面脚本已断             | 先看有没有「看门狗」日志；仍不动就点「停止」→「开始」            |

### 换平台后必须确认的三件事

1. 面板顶部的平台高亮 = 你想要的平台
2. 登录自检显示「已登录」（两个平台的登录互不影响，切平台不会掉线）
3. 今日额度与任务文案是该平台的（比如鱼泡 0/100、BOSS 72/50）

## 十六、合规与风险（请先读完再用）

本扩展是**本地模拟点击**工具，不是平台官方工具，使用风险由使用者承担：

1. **可能违反平台用户协议**：自动化操作可能被判定为异常行为，导致限制投递、限制登录甚至封号。
2. **不做任何规避**：不破解、不伪造请求、不绕过验证码。遇到风控一律停下，绕过验证码不在本工具的能力范围。
3. **发送内容由你负责**：招呼语文案、投递频率、目标岗位均由你设定，请遵守招聘平台规则与相关法律法规。
4. **仅建议小规模、低频率、人工复核式使用**：把筛选和初筛交给工具，把判断留给自己。
5. **数据只在本机**：卸载扩展或清理浏览器数据会导致记录丢失，重要配置请定期「导出配置」备份。

作者不对因使用本工具导致的账号处罚、数据丢失或任何间接损失负责。

## 十七、已知限制

| 限制           | 说明                                                  |
| ------------ | --------------------------------------------------- |
| 只在已登录的浏览器里工作 | 不处理登录、不代填验证码，登录必须人工完成                               |
| 依赖页面结构       | 平台改版后选择器可能失效，需要重新校准（设置页可改，无需改代码）                    |
| BOSS 翻页靠 URL | 列表是无限滚动，第 4 页后平台可能返回与第 1 页相同的列表，此时判定到末页并停止          |
| 鱼泡每个岗位开新标签   | 详情页在独立标签打开，会看到标签频繁开关，属正常行为                          |
| 定时按当前平台      | 两个平台的定时不并行，要跑哪个平台先切过去                               |
| 每日上限按平台独立    | BOSS 与鱼泡各自计数，互不占用                                   |
| 旧记录无平台字段     | v2.9 之前写入的投递记录没有 `platform` 标记，数据页「平台」列显示 `-`，不影响去重 |
| 选择器候选顺序敏感    | 自定义选择器按列表从上到下尝试，把最精确的放最上面                           |
